# agent-skills

Claude Codeを利用したソフトウェア開発を、再現可能かつ継続的に改善できる形で標準化するためのSkillプラグインです。

Platform Engineeringの観点から、Issueの具体化、設計、実装、レビュー、検証、リリースまでの開発プロセスをClaude Codeから実行可能な手順として整備します。

## 目的

このリポジトリの目的は、個別のプロジェクトやツールに閉じたプロンプトを集めることではありません。

複数のチーム、リポジトリ、技術スタックで再利用できる開発標準をClaude CodeのSkillとして提供することを目的とします。

各Skillは次の状態を目指します。

- 開発作業の目的、入力、判断、出力、終了条件が明確である
- 実行結果を人間が確認できる
- 同じ作業を異なるリポジトリでも再現できる
- プロジェクト固有の事情を明示的に差し込める
- 標準から外れる場合に、その理由と影響を確認できる
- 実際の利用結果から継続的に改善できる

## 対象

このリポジトリはClaude Code向けに設計します。

SkillはClaude Codeプラグインとして提供し、次の形式で呼び出せることを前提とします。

```text
/agent-skills:<skill-name>
```

Claude Code固有の機能は、Skillの安全性、再現性、操作性を高める場合に利用します。

一方で、開発プロセスそのものは特定のモデル、クラウド、Issue Tracker、CI/CDサービスに過度に依存させません。

## 設計原則

### 成果と証拠を標準化する

特定のツール操作ではなく、達成すべき状態と、その状態を確認するための証拠を定義します。

たとえば「特定のCIサービスを実行する」ことではなく、「変更に必要な検証が実行され、結果を追跡できる」ことを標準とします。

### 標準と実装手段を分離する

Skillの中核には、複数のプロジェクトで共通する判断基準とプロセスを記述します。

GitHub、GitLab、Jira、Linear、各種CI/CDサービスなどに固有の処理は、中核から分離したアダプターまたは参照情報として扱います。

### 安全な既定値を提供する

設定が存在しない場合でも、安全かつ説明可能な動作を選択します。

破壊的な操作、外部への公開、本番環境への変更、権限の拡大などは、Skillが暗黙に実行してはなりません。

### カスタマイズ箇所を明示する

プロジェクト固有の要件をSkill本文へ埋め込まず、変更可能な判断として明示します。

少なくとも次の内容は、プロジェクトごとに変更できる可能性があります。

- 利用するIssue Tracker
- ソースコード管理サービス
- CI/CDの実行方法
- 必須のレビューおよび承認
- テストと品質ゲート
- セキュリティ要件
- デプロイ方式
- リリース判定
- 証拠として保存する成果物

### 標準からの逸脱を隠さない

標準をすべての状況へ強制的に適用することは目的としません。

標準を適用できない場合は、逸脱した内容、理由、影響、代替措置を明示します。

### 段階的に情報を読み込む

`SKILL.md`には、Skillを実行するために必須となる手順と判断だけを記述します。

詳細な基準、ツール固有の手順、例、テンプレートは、必要になった時点で読み込めるように分離します。

### 実行可能性を検証する

Skillは文章として妥当であるだけでは完成としません。

実際の開発タスクに適用し、Claude Codeが期待する判断と出力を再現できることを検証します。

## 参照する考え方

開発標準を設計する際は、CNCFおよびGoogleが公開するCloud Native、SRE、Platform Engineering、ソフトウェアデリバリーのプラクティスを主要な参照情報として扱います。

ただし、外部のプラクティスをそのまま規則として転記しません。

各Skillでは、参照した考え方、採用する理由、適用範囲を明らかにし、このリポジトリの目的に合わせて具体化します。

## Skillの構成

```text
agent-skills/
├── .claude-plugin/
│   └── plugin.json
├── skills/
│   └── <skill-name>/
│       ├── SKILL.md
│       ├── references/
│       ├── scripts/
│       └── assets/
└── README.md
```

各Skillは自己完結したディレクトリとして管理します。

- `SKILL.md`: 実行手順と判断基準
- `references/`: 必要な場合だけ読み込む基準や詳細情報
- `scripts/`: 再現性が必要な検証や生成処理
- `assets/`: 出力に利用するテンプレートや静的ファイル

不要なディレクトリは作成しません。

## Skillの受け入れ基準

Skillを追加する前に、少なくとも次の内容を確認します。

- 対象となる具体的な利用場面がある
- 複数のプロジェクトで再利用できる
- 入力と期待する出力が明確である
- 重要な判断と終了条件が明確である
- 実行結果を確認するための証拠が定義されている
- プロジェクト固有の内容が中核から分離されている
- 失敗時および情報不足時の動作が定義されている
- 不要な権限や破壊的操作を要求しない
- Claude Codeで実際に検証できる
- Skillの説明と実際の動作が一致している

## 対象外

このリポジトリでは、次の内容を横断的な標準Skillとして扱いません。

- 単一リポジトリでしか成立しない手順
- 特定のチームだけが理解できる暗黙のルール
- 特定ツールの操作だけを目的とした手順
- 実行結果や終了条件を確認できないプロンプト
- Claude Codeが本来持つ一般的な能力の言い換え
- 利用実績のない網羅的なチェックリスト

プロジェクト固有の手順は、各プロジェクトの `.claude/skills/` で管理します。

## 開発方法

Skillは一つずつ設計、確認、検証します。

1. 具体的な利用場面を定義する
2. 標準化する成果、判断、証拠を定義する
3. カスタマイズ可能な箇所を分離する
4. `SKILL.md`と必要なリソースを作成する
5. Claude Codeで実際のタスクに適用する
6. 結果を確認して改善する
7. 受け入れ後に次のSkillへ進む

複数のSkillを先に作り込まず、実際の利用から得られた知見を次の標準へ反映します。
