# Default Issue Templates

プロジェクト固有のIssueテンプレートがない場合に使用する。

必要のない見出しや空の項目は追加しない。

## Task

```markdown
## 目的

{この作業によって解決する課題と、実現したい状態}

## 背景

{現在の状態、影響、課題だと判断できる根拠}

## 解決方針

{現状と望ましい状態の差を、どのように埋めるか}

## 対象範囲

- {今回変更する範囲}

## 対象外

- {関連するが今回変更しない範囲}

## 検証方法

- {期待する振る舞いを確認する方法}

## 完了条件

- [ ] {課題が解決したと判断できる条件}
```

## Bug

```markdown
## 発生したこと

{実際に確認された振る舞いと影響}

## 期待する振る舞い

{課題が解消された状態で観測される振る舞い}

## 再現方法

1. {再現手順}

## 環境

- {発生を確認したバージョンや実行環境}

## 調査結果

{確認した事実、関連するコードや状態の流れ}

## 原因または差

{期待と実際の振る舞いに差が生じる理由}

{原因を確定できない場合は、確認できた発生条件と、修正方針が作用する差}

## 修正方針

{原因または差へ作用し、期待する振る舞いを回復する方針}

## 対象範囲

- {今回変更する範囲}

## 対象外

- {関連するが今回変更しない範囲}

## 検証方法

- {問題の解消と再発の検知方法}

## 完了条件

- [ ] {課題が解決したと判断できる条件}

## 補足

{ログ、スクリーンショット、関連Issue、調査資料など}
```

## 判断依頼

単に「どうしますか」と尋ねず、判断に必要な事実、選択肢、推奨を示す。

```markdown
## 判断が必要なこと

{決める必要がある事項}

## 確認できた事実

- {コードや実行結果から確認した事実}
- {関連する制約}

## 選択肢

### A. {選択肢}

- 課題への効果:
- 影響範囲:
- トレードオフ:

### B. {選択肢}

- 課題への効果:
- 影響範囲:
- トレードオフ:

## 推奨

{推奨する選択肢と、その理由}
```

実際に成立する選択肢だけを提示する。数を揃えるための選択肢は作らない。
